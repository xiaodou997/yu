# macOS IME Spike：2026-08-09

## 环境

- macOS / AppKit
- 自定义 `NSView`
- `NSTextInputClient`
- Swift Package experiment

## 已观察事件

实际启动 spike 后，中文拼音输入产生连续 `setMarkedText`，选词后产生一次 `insertText`：

```text
setMarkedText preedit="y"
setMarkedText preedit="yi"
setMarkedText preedit="yin wen"
insertText commit="引文"
```

另一次输入成功提交 `日语`。emoji 候选提交 `😊` 时，AppKit selection 前进 2 个 UTF-16 code
units，符合系统 `NSRange` 的坐标语义。

## 发现的问题

Escape 取消 composition 时，系统发送 `cancel:` command。第一版 spike 没有处理该命令，而且
为了显示 preedit 已经临时替换了 TextKit storage，因此无法可靠恢复原选择内容。

修正后通过 LaunchServices `.app` 重新实测：输入 `yu yan` 时 preedit 正常显示下划线，Space
提交为 `语言`；随后输入 `shi` 并按 Escape，preedit 被完整移除，正文仍为 `语言`。测试结束后
恢复了此前的系统输入源。

## 架构结论

Rust core 不应在 `setMarkedText` 时修改 `TextBuffer`。正确协议为：

```text
setMarkedText ──► CompositionOverlay update ──► projection/layout only
insertText    ──► one Transaction             ──► TextBuffer
cancel        ──► drop overlay                ──► zero Transaction
```

Swift spike 暂时保存 composition 开始前的 attributed substring，用于验证 Escape 回滚；产品
实现不会依赖这份备份，因为 canonical source 从未被 preedit 修改。
