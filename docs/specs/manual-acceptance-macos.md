# macOS 人工验收清单

自动化测试到不了的地方。这里列的每一条都需要人坐在机器前操作真实输入法、
真实 VoiceOver、真实鼠标——不是因为懒得写测试，而是因为被测的对象是
macOS 自己的行为。

验收对象是产品 app，不是任何实验壳：

```bash
platform/macos/yu-shell-macos/run-app.sh <文件>
```

> `open` 对运行中的 app 只激活不重启，改动后必须用 `run-app.sh`。

自动化覆盖的部分见 `tools/verify.sh`（Rust 测试 + 10 个 headless self-check）
与 `--launch-window-self-check`（真实 NSWindow 下的帧调度与可滚动范围）。

---

## A. IME

切换到真实输入源后逐条确认。Yu 不会替你切换输入法。

**A1. 拼音/罗马字的 preedit 只改变 marked range。**
输入过程中 canonical source 不变、Undo 里不出现中间态（不变量 H1、H2）。

**A2. 选词只产生一次 commit。**
不是「先删再插」，也不是每次候选变化都提交一次。

**A3. candidate window 跟随 caret。**
多行 preedit 时锚定在**第一个视觉 fragment**，不能因为取整个 marked range
的并集而跳到后面的行。

**A4. Escape 取消后正文完全恢复。**
包括 caret 位置与选区。

**A5. emoji 与组合字符退格不产生无效序列。**
`👨‍👩‍👧‍👦`、`é`（e + U+0301）、`🏳️‍🌈` 各删一次，看剩下的是不是合法字形
（不变量 H7）。

**A6. dead key。**
`´ + e = é`、`` ` + a = à``、`^ + o = ô`、`~ + n = ñ`。

建议的场景标签（便于记录）：`japanese-romaji`、`japanese-kana`、
`pinyin`、`combining-accents`、`dead-key`。

## B. Accessibility

需要开启 VoiceOver，并给终端或 app 授予 Accessibility 权限。

**B1.** 整份文档作为一个 `AXTextArea` 暴露，朗读顺序与视觉顺序一致。
**B2.** 移动光标时 VoiceOver 报出正确的行与位置。
**B3.** composition 进行中，AX 值、`NSTextInputClient` 与屏幕上画的是
同一份 overlay（不变量 H3）。
**B4.** 表格分隔线可用 VoiceOver 聚焦，increment/decrement 改变列宽且
不修改 Markdown 源码。

## C. 渲染

headless self-check 覆盖不到「画出来对不对」。

**C1.** 中文、日文、emoji、阿拉伯文、希伯来文都能显示，不出现豆腐块。
**C2.** Retina 与非 Retina 屏之间移动窗口，字形保持清晰。
**C3.** 缩放窗口后按新宽度重排，没有残留的旧帧。
**C4.** 长文档滚到底能看到最后一行；打开时停在开头。
**C5.** 图片解码完成后替换 placeholder，后面的文字跟着重排一次，位置不跳。
S6 第七刀之后图片是一个真正的 widget：盒子在行里占宽度、把行撑高，而不再是
排完之后贴在替代文字上面的一块。所以这一条现在还要看**它下面的块有没有跟着
往下挪**——挪不动就是块高与画出来的几何不是同一套。
**C6.** 引用条与表格网格衬在文字**下面**（单元格底色盖不住自己的文字），
任务框压在文字**上面**；点一下任务框能切状态。S5 的前后截图对比抓到过一次
任务框跑到文字底下——不 panic、不报错，headless 也看不见（那条 self-check
断言的是命中判定，与画家顺序无关）。
**C7.** 在引用块或列表项的左侧 gutter 里点一下，光标落在内容起始处，
不是块的左边缘；在软换行的行末与下一行行首各点一下，光标分别停在这两处。
**C8.** 在一行混排里（`abc مرحبا def`）逐个字点过去，光标每次都停在**点到
的那个字**的边上，不跳到行的另一头。S6 把文字流的命中测试换成
`BlockLayout::hit` 之后，性质测试压得住「落在最近的 caret 上」，但那是在
等宽度量下算出来的几何；真实字体的 RTL 连写与 shaping 只有真实窗口看得见。
**C9.** 光标走进 `![替代](目标)` 里，图片让位、整段源码露出来可编辑；走出去
图片回来。再在图片盒子的左右两边各点一下，光标分别停在盒子的左沿与右沿——
这两处是同一个视觉偏移上的两个位置，只有 bias 分得开，分错了光标会画到盒子
的另一边去（性质测试压得住等宽度量下的这一条，真实字体下只有窗口看得见）。
**C10.** Setext 标题（`标题` 下面跟一行 `===` 或 `---`）画成一个放大的标题，
下划线那一行不出现——**也不留一个空行**。光标走进去，`===` 露出来可编辑；走出去
它收回去。S6 第十一刀 b 之前这两行是一段普通正文，块的身份改由语法树给之后才
认得它。「不留一个空行」是这一条的重点：隐藏区间少藏一个换行符不报错、不少字，
只是标题下面多一条空白。
**C12.** 多光标下的 caret 与选区底色（第四刀）：N 根 caret 全部画出来，**每一根
都压在选区底色之上**（caret 是最后一层）；跨块的多光标——两根光标分别落在标题块
与段落块里——两根的高度各自跟着**自己那一行的行盒**，不是同一个基准行高。
第三刀的教训就在这里：底色高度用基准行高的毛病自动化断言看不见。

**C13.** 代码块高亮（第五刀）。语料用 `Fixtures/render-code.md`。
自动化压住了「颜色算对了」与「颜色进了这一帧」（四层用例 +
`--code-highlight-self-check` + `--launch-window-self-check` 第 11 步）。
**剩给这里的是「看着对不对」，那件事一条断言也压不住**：

- 关键字、字符串、注释、类型、函数名各是一种颜色，而且**在 `(245,246,248)` 的
  代码块底色上都读得清**——第三刀与第四刀各抓到过一次颜色合成问题，两次都是
  自动化全绿之后才看见的。
- **没被着色的字（空格、标识符、括号）与代码块外的正文是同一种黑**，不是灰。
- **等宽没有丢**：着了色的 `fn`、`let` 与没着色的空格**竖着对得齐**。
  `winner_over` 只让最窄的 Mark 赢，token 那条盖掉整段的 `Code` 就会让高亮的字
  掉出等宽字体——列会歪，但一条断言都不响。
- 没有语言名的那个代码块（fixture 里第三块，正文与第一块完全相同）**一个字都
  不着色**，与第一块并排看得出差别。
- 光标走进代码块、在里面上下左右移动：**颜色一动不动**，不闪、不重排。
- 在代码块里打字（比如把 `let` 改成 `lets`）：颜色跟着改，中间不出现整块变黑
  或整块变色的一帧。**「颜色跟着改」这半句已经自动化了**——
  `--code-highlight-self-check` 断的是「高亮字形正好少 3 个」，比截图强，也
  比真人把光标准确放进代码块可靠（方向键会滚视口，合成事件驱动不了 AppKit）。
  这里剩下的是「中间那一帧好不好看」。
- **深浅两种外观都要看一遍。** 深色那一份不是把浅色反相——每一份按自己那块
  代码块底挑对比度（浅色 `(245,246,248)`、深色 `(34,38,45)`）。
  ~~深色外观下这一条不通过是已知的，与第四刀记录里的 D2 同一个原因：文档区
  背景写死为白。~~ **「深色模式」那一刀之后不成立了**，留着划掉的原文是因为
  它是一条**说明会随着别处的修复而过期**的实例。

**C14.** 引用标签的 full case folding（第六刀的 F3）。语料两行并排——
`[ẞ]` 配一条 `[SS]: https://…` 的定义，紧挨着一行 `[没定义]`。
第一行的方括号**藏起来**、文字按链接的样子画；第二行的方括号**留着**、
整行按源码画。**只有并排才看得出来**：这个 bug 单独看第一行的样子，与
「一条没定义的引用」一模一样（S6 第十三刀踩过同一个坑，那次也是两行并排
才看出来的）。自动化压住了装饰这一侧（`yu-markdown` 的用例断在隐藏区间上），
这里剩下的是「藏的那一段真的没画出来」。

**C11.** 嵌套列表项（`  - 内`）画成缩进一级的 `•`，前面的 `- ` 不出现；嵌套的
任务项（`  - [x] 内`）**同样往右让一级**，它的 `- ☐` 原样留着（任务项按设计不
换替代标记）。两件事分别在两刀里修的：第十一刀 b 之前列表项的标记装饰指着
**外层**那一项的 `-`、自己的 `  - ` 原样留在正文里；第十二刀之前任务项一列都
不让，因为缩进挂在标记装饰上而它没有标记。

## D. 大纲面板

自动化压住了层级、导航、刷新后的状态与「滚动真的发生了」（前三条在
`--outline-panel-self-check`，最后一条在 `--launch-window-self-check`）。
**剩给这里的只有外观与焦点**——那几件 headless 一件也看不见。
语料用 `Fixtures/outline.md`。

**D1.** 拖分栏分隔线，面板宽度跟着走，最窄 150 点、最宽 420 点都拖得到，
松手后文档按新宽度重排且没有残留的旧帧。缩放窗口时**面板宽度不变**，
由文档吸收——反过来（面板跟着缩）会把大纲挤没。
**D2.** 深色与浅色各看一次：面板底色、选中行、层级缩进的折叠箭头都跟着换，
不出现「浅色面板配深色文档」。切换外观后再拖一次分隔线。
**D3.** 面板上显示的是**剥掉语法标记之后**的标题（第三刀开了回报区间的
FFI）：`## 带 **行内标记** 的标题` 显示成 `带 行内标记 的标题`，
`## 带 [链接](https://example.com) 的标题` 显示成 `带 链接 的标题`，
`收尾串` 不带收尾的 ` ##`，Setext 的 `多行 标题` 折成一行。
**把光标停进某条标题的 `**` 里，面板上那一行不能跟着长出 `**`**——面板走的
是规范装饰，不是带光标露出的那一份。fixture 里那条 `> # 容器里的标题`
**不出现**在面板上——这是「块的边界还没合并」那道闸门后面的已知欠账，
不是回归。
**D4.** 焦点：点面板里的一条，光标跳到文档里对应的标题且视口滚过去；
此时键盘焦点留在面板，上下键能在条目间走。`⌥⌘1` 收起面板，焦点回到文档，
菜单项上的勾跟着变；再按一次展开，展开状态与选中行还在。
（第三刀把其中两条挪进了 `--launch-window-self-check` 第 9 步：**菜单项上的勾**
与**收起后焦点不留在面板上**。剩下要人按键盘的只有「上下键在条目间走」，
那是 `NSTableView` 自己的行为。）
**D5.** 在文档里改一个标题的文字，面板上那一行**跟着变**；在中间插一条新
标题，它出现在正确的层级下，而**已经折叠的那几条仍然是折叠的**。

## E. 搜索

自动化压住了剥标记、上下文裁进块、导航与环回（`--search-panel-self-check`），
以及**高亮真的进了屏幕上那一帧**（`--launch-window-self-check` 第 7–8 步，
实测 `search=1→0`）。剩给这里的仍然只有外观与焦点。
语料用 `Fixtures/search.md`。

**E1.** `⌘F` 打开搜索面板，键盘焦点落在查询框里，可以直接开始打字。再按
`⌥⌘2` 收起，面板消失、**文档里的高亮一起消失**，焦点回到文档，菜单项上的勾
跟着变。
**E2.** 边打字边看：每敲一个字符，文档里的黄色底色与结果列表一起跟着变。
**打到一个没有匹配的查询时，底色必须一处不剩**——留下上一次的底色是这一刀最
可能的静默失败。
**E3.** 深色与浅色各看一次：命中的黄色与「当前命中」的橙色在两种外观下都要
和正文分得清，选区（半透明蓝）压在命中上时两者都还看得见。
**E4.** `⌘G` / `⇧⌘G` 在命中之间走，走到文档外面的命中时**视口滚过去**；
走到最后一处再按一次**环回到第一处**。当前那一处的底色是橙的，其余是黄的，
结果列表上高亮的行跟着走。
**E5.** 在文档里点一下（离开任何命中），列表上的高亮消失、底色全变回黄色；
点一条结果，那一段被**选中**（不是只放光标），底色变橙。
**E6.** 编辑文档：在文首插入几个字，全部底色跟着整体挪，不会有一处停在原地。
**E7.** 搜索区分大小写（已登记的欠账）：`Yu` 与 `yu` 是两个不同的查询。

## F. 多光标

自动化压住了一组选区的不变式、N 条 edit 真的都生效、undo 是一步、AX 复数属性
（`--multi-cursor-self-check`），以及 **N 根 caret 与 N 块选区底色真的进了屏幕上
那一帧**、⌥ 点的坐标→源码那一步（`--launch-window-self-check` 第 10 步，实测
`carets=1→2`、`multiSelection=2`）。剩给这里的是**画出来对不对**与几条降级的
可见行为。语料用 `Fixtures/multi-cursor.md`。

**F1.** ⌥ 点几处，屏幕上出现几根光标，**每一根都在你点的那个字边上**，粗细与
颜色和单光标时一样，都在闪。在一段已有选区的边界上 ⌥ 点一下，**不会多出一根
贴着选区的竖线**（那一根要被并进选区）。
**F2.** `⌘F` 搜一个出现多次的词，`⌘⇧L` 选中全部匹配：每一处都套上选区底色，
**相邻的两处之间看得出是两段**（语料里 `aa` 与 `aaaa` 就是这个形状），不是连成
一片。然后直接打字，每一处同时被替换。
**F3.** 接着按一次 `⌘Z`：**所有处一起回来**，不是只回来一处。再按 `⇧⌘Z` 一起
去掉。
**F4.** 多光标下按 ←/→/↑/↓，每一根都跟着走；按住不放连续走，没有哪一根掉队或
突然并到别处。**已登记的降级**：N>1 时 ↓ 连续穿过一行短行会左漂（不吃粘滞列），
这是预期行为，不是回归。
**F5.** 多光标下按 Esc 或在文档里单击一下，塌回一根光标。
**F6.** 深色与浅色各看一次：多根 caret 与多块选区底色在两种外观下都要看得清，
底色压在文字上时文字仍然可读。
**F7.** **已登记的降级，确认它们是「按设计」而不是坏了**：多光标下按 Enter 只插
换行、不续列表前缀；多光标下缩进/反缩进只作用在主光标那一行；开始输入中文
（IME）时光标塌回一根。

## G. 剪贴板导出（第六刀）

自动化压得住「HTML 是对的」（`yu-export` 的用例、CommonMark 的 652 条棘轮）与
「Yu 自己粘得回来」（导出→导入的不动点）。**压不住的是别的 app 怎么显示它**
——而那正是导出存在的理由。

**G1.** 在 Yu 里选中一段混排（标题 + 粗体 + 链接 + 任务项 + 表格 + 围栏代码
块 + 一条 `---`），⌘C，粘进一个**富文本**收件方（备忘录 / Pages / 浏览器的
可编辑区）。标题是标题、粗体是粗体、链接可点、任务项是一个复选框、表格是
表格、代码块等宽、`---` 是一条横线。**第六刀之前 `---` 会粘成三个字符、
表格的对齐会丢、链接的 title 一律不见**。

**G2.** 同一段 ⌘C 之后粘进一个**只认纯文本**的收件方（终端）。出来的必须是
**Markdown 源码原样**，不是 HTML 标签，也不是去掉语法的白文本。

**G3.** 从**浏览器**里拷一段富文本（一个带链接与列表的网页片段），粘进 Yu。
认得的结构变成 Markdown；认不出来的整段降级成纯文本，**不出现半截 HTML**。
第六刀放宽了三处属性（`<hr>` / `title` / `align=`），要确认放宽没有把
`<div>` / `<script>` 这类原始 HTML 一起放进来。

**G4.** Yu → Yu 自己：在 Yu 里 ⌘C 一段带表格与硬换行的文本，在同一个文档里
⌘V。粘回来的表格**保着对齐**，硬换行**还是一个段落**（不是两段）。
第六刀之前后两件事各有一个静默的 bug，都是那条不动点断言抓出来的。

#### 发现一：Yu 的 HTML flavor 不声明编码，收件方按传统中文编码猜

**做了一次决定性实验**：把**同样的字节**前面加上 `<meta charset="utf-8">`
再放回剪贴板，粘进同一个 TextEdit——中文**立刻全对**。

> **自动化压不住它，而且压不住的方式很典型**：`yu-export` 那几条断言问的是
> 「HTML 对不对」，字节本身完全正确；`--clipboard-self-check` 问的是「Yu 自己
> 认不认得」，Yu 用的是 canonical 的 Markdown flavor，根本不走这条路。
> **没有任何一条判据问过「别的 app 会用什么编码读它」**，而那正是导出存在的
> 理由。
>
> **不在第七刀 c 里修**：c 是纯重构，判据是「画面逐字节不变」，掺一个行为
> 修复进去会让那个判据说不清自己在证明什么。而且这个修复里有一个真的设计
> 选择要先定（见下），不是一行的事。**登记在案。**

修的时候有两个位置，选哪个要连着下一条一起想：

1. **只在剪贴板那一层加**（`ClipboardPayload::html()` 或平台写 flavor 那一步），
   `export_html_fragment` 不动。好处是 `yu-export` 现有的断言与「导出→导入」
   不动点一个字都不用改；代价是 Yu 自己发出去的 HTML 从此**过不了自己的导入
   白名单**（`meta` 不在名单里），多一处不对称。
2. **同时把 `meta` 加进导入器的忽略集合**，于是 Yu 仍然接得住自己发的 HTML。
   这一条顺带就把下面那条发现的一半解决了。

> **已修（同一次会话）**：`<meta charset="utf-8">` 加在 `ClipboardPayload::html`
> 那一层，`export_html_fragment` 仍然是一段不带编码的片段；导入器把顶层的
> 编码声明当信封摘掉，好让「自家导入器接得住自家导出」在剪贴板这条路上继续
> 成立。四个变异全红，真实窗口复验过：同一份文档粘进 TextEdit，中文全对。

#### 发现二：导入白名单拒掉了每一个真实浏览器

`html_import.rs::ensure_allowed_tag` 的名单里**没有** `div` / `span` / `html` /
`head` / `body` / `meta`。而**任何浏览器**拷出来的 HTML 都至少带其中之一
（Chrome 实测：`<html><head>…<body>` 加 `<!--StartFragment-->` 加 `<div>`）。
于是「从网页拷一段富文本粘进 Yu」这条路上，**HTML 导入器从来没有生效过**，
每一次都退回纯文本。

**自动化把这个行为钉成了「有意的」**：`Fixtures/clipboard/browser-wrapper.html`
（内容正是浏览器那种包裹）在 `--clipboard-self-check` 里断言的就是**被拒**，
而且是绿的。第六刀登记的那条「原始 HTML 继续拒」说的是 `<div>raw</div>` 作为
**内容**；没有人问过：**包裹**也算内容吗？

> **这是「两道门挡同一件事」的另一张脸**：白名单同时挡着「别人的 HTML 语义」
> 与「浏览器的包裹」，而只有前者是想挡的。判据没错，**语料替真实输入说了话**
> ——fixture 断言它被拒，于是没有人再去看被拒之后用户看到了什么。
>
> **已修（同一次会话），而且修下去之后发现挡着它的不止一样。**

#### 发现三：HTML 导入这条路在生产里从来没有被走到过

平台侧取剪贴板的顺序原来是 **Markdown > 纯文本 > HTML**（`sourceFromPasteboard`），
而**任何真实剪贴板都带纯文本**——浏览器、邮件、文档编辑器无一例外。于是
`importHTML` 这条分支**一次都没有被调用过**：白名单、它的用例、它的 fixture，
全都在为一条不可达的分支服务。

**没有任何断言看得出来**，原因很具体：clipboard self-check 的每一条都是自己
往私有剪贴板上摆格式，而它摆的四种组合里**恰好没有「纯文本与可用 HTML 同时
在」**——那正是每一个真实剪贴板的形状。self-check 打印出来的那句
「Markdown > 纯文本 > 严格 HTML」还把这个顺序当成结论写着。

> **这是「语料替真实输入说了话」的第二个实例**（第一个是 `browser-wrapper`
> 那条 fixture 断言「被拒」）。两次都是：判据本身没写错，是**造出来的输入
> 造不出真实的形状**，于是绿着的断言把一个洞钉成了「有意的」。

顺序改成 **Markdown > HTML > 纯文本**。纯文本按定义是同一份内容丢掉结构之后
的样子，两者都在时取纯文本等于每次都主动选那份更少的。回退机制没有变
（`importHTML` 在策略拒绝时返回 `nil`），只是现在真的会走到。新增一条断言
补上那个缺掉的组合，判据刻意让两条路产出不同的字符串——否则断言什么都证明
不了。

（右下角圆角处，蓝通道 +1）会被读成「渲染变了」**——它比噪声底小三个数量级。
这是陷阱 5/32 那一族的第三张脸：**判据不只要门控拍摄条件，还要先量出噪声底**。

`render-code.md` 是这一刀最该看的语料：代码高亮把一行切成多个 `StyledRun`，
每个 run 单独 shape（已登记的那条），所以它是对「字形怎么铺满 run」最敏感的
一份。它连全图都是 0。

**陷阱 35 的判据要更正**：`已保存 · Rev 0` **不在窗口标题上**（那里只有文件
名），在窗口里那个 AX description 为「文档状态」的标签上
（`DocumentWindow.updateStatus` 把它写进 accessibility value）。读法：
`value of (first UI element of window 1 whose description is "文档状态")`。

### S7 第六刀（导出 comrak + F3）· Apple M1 Max · macOS 26.5

跑了 **C14**（F3 的引用标签 full case folding），**深色外观**，语料是
scratchpad 里的 `f3-window.md`——`[ẞ]` 配一条 `[SS]: https://…` 的定义，紧挨着
一行 `[没定义]` 作对照。深色不影响这一条：文档区背景写死为白（第四刀记录里的
D2），要看的只是方括号藏没藏。

**判据是逐像素比对，不是肉眼。** 旧版（22683c4，第五刀那一版）建在一个独立的
git worktree 里（自己的 target 目录，陷阱 6），两版各拍一张 BMP，同一窗口几何
（1009,283,900,652）、同一外观（拍前拍后各查一次，两次都是 Dark）：

| 差异段 | 像素数 | 最大通道差 | 平均 | 判定 |
| --- | --- | --- | --- | --- |
| 行 21–42（标题栏文字） | 961 | **2** | 1.3 | AppKit 抗锯齿噪声，不是渲染变化 |
| 行 559–591（`[ẞ]` 那一行） | 15,941 | **255** | 128.2 | 就是这一刀 |

**结果：通过。** 旧版两行画得一模一样——`[ẞ]` 与 `[没定义]` 的方括号都留着，
一条写对了的引用长得和一条没定义的完全一样。新版第一行的方括号藏起来、
只剩 `ẞ`，第二行原样。**只有并排才看得出来**，S6 第十三刀踩过同一个坑。

**G 节（剪贴板导出）这一刀没跑**，欠着。自动化压住的是「HTML 对不对」与
「Yu 自己粘得回来」；G1–G4 要的是**别的 app 怎么显示它**，那件事没有断言。

**新踩的一个坑，已经写进陷阱表**：第一次拍新版时前台判据过了，图却是废的
——标题栏写着 `Rev 1 · 未保存`，正文里多了两个字符。**「前台是 Yu」不够，
还要确认文档没被动过**（`已保存 · Rev 0`）。差分会把那次编辑算成渲染变化。

### S7 第五刀（代码块高亮）· Apple M1 Max · macOS 26.5

跑了 **C13 全部条目（浅色）**，语料是 `Fixtures/render-code.md` 的一个扩写本
（rust / python / json 三块，外加一块**与第一块正文完全相同但没有语言名**的对照
组），放在 scratchpad 里。驱动方式：`run-app.sh` 起窗口 + 方向键（`key code`，
不经输入法）；**每一张截图前都先确认前台进程是 Yu**——中途被别的窗口抢过一次
前台，拍到的是另一个 app 的画面，差分整张图都不同（陷阱 5 的另一张脸）。

**判据不是肉眼，是像素。** 把截图转成 BMP 逐像素统计「墨色」（三通道和 < 400）：

| | 实测 |
| --- | --- |
| 着色块的主色 | `(207,34,46)` 关键字、`(111,119,129)` 注释、`(10,48,105)` 字符串、`(149,63,25)` 类型、`(6,80,174)` 数字/常量、`(0,0,0)` 未着色 |
| 无语言名的那一块 | **只有 `(0,0,0)` 与它的抗锯齿灰阶，一个彩色像素都没有** |
| 块外正文 | 同样只有 `(0,0,0)`——「没着色的字与正文是同一种黑」成立 |

调色板逐值对上了 `viewport_code_role_color`（注释差 1，是子像素抗锯齿）。

**等宽没有丢**：着色块与对照块的每一行，左端与右端的 x **逐行一致**（445/586、
479/623、478/757、478/818、448/452），差值 ≤ 2 像素（抗锯齿）。这条压的是
「token 化把一次 shaping 变成 N 次之后度量变了」——没变。

**光标进代码块颜色不动**：在同一屏内左移一个字符，前后两张截图**主色集合完全
相同**，差异只有 700 个像素（caret 自己 + 滚动条淡出），占全图 0.03%。

**没跑的**：**深色外观**——它不通过是已知的，与第四刀记录里的 D2 同一个原因
（文档区背景写死为白），这一刀没有让它更糟也没有修它。**「在代码块里打字」那一条
改成了自动化**（`--code-highlight-self-check` 断「let→lets 高亮字形正好少 3」，
实测 7→4）：真人按键盘那条路把光标准确放进代码块不可靠——方向键会滚动视口，
而合成点击驱动不了 AppKit（陷阱 25）。

**第四刀欠着的 F 节与 A 节这一刀没有补跑**，范围不变。

### S7 第四刀（多光标）· Apple M1 Max · macOS 26.5

跑了 **F1（⌥ 点的一半：见下）、F2、F6（浅色）、C12**，外加 A 节全部条目在
「组字前先塌回一根光标」这条降级下重跑一遍的**结果确认**（A1–A6 行为不变，
因为 `begin_composition` 一进门就塌回单光标，IME 那条路与多光标之前完全相同）。

语料是 `Fixtures/multi-cursor.md` 的一个变体（标题里也放一个 `alpha`，用来看
跨块的三根光标）。驱动方式：`System Events` 点菜单项（**这条有效**，见陷阱 25
的例外）。

**结果：F2 / F6 / C12 通过。截图抓出一个自动化断言看不见的缺陷，已修并配了
断言**（见 overview S7 第四刀「截图抓出来的一件事」）：

1. 「选中全部匹配」之后，非当前的那几处命中把黄底垫在半透明选区之下，合成出
   一块脏灰绿——与第三刀在当前命中上抓到的是同一族颜色。修法是**被选区完全
   盖住的普通命中不画**。

确认通过的：三根光标分别在标题块／段落块／列表项里时，**三块底色与三根 caret
的高度各自跟着自己那一行的行盒**（C12）；当前命中（主光标那一处）仍然标成褐橙、
其余是干净的选区蓝，主光标是哪一根看得出来；caret 压在底色之上。

**没跑到的**：F1 的 ⌥ 点手感、F3（`⌘Z` 一次全回）、F4（多光标下的方向键与
粘滞列左漂）、F5（Esc 塌回）、F7（三条降级），以及 **F6 的深色**与 **A 节的
实际输入法操作**——这几条要真人按键盘/切输入源。自动化侧对应的断言分别在
`multi_cursor.rs`（F3/F4/F7）、`--multi-cursor-self-check`（F5/F7 的 IME 那条）
与 `--launch-window-self-check` 第 10 步（F1 的坐标→源码那一步）。

**D2 有一条不通过，但不是这一刀引入的**：深色外观下面板跟着变深，而**文档
区仍然是白底**。渲染配置里的背景色写死为 `Rgba8::white()`（不变量 I5 要求这
一帧自己画背景），注释里已经写明「暗色模式需要平台把实际的
`textBackgroundColor` 传进来」。浅色外观下这一条是通过的。

**没跑的**：D1（分栏拖动）、D5（编辑后面板刷新）、E6（编辑后底色整体挪）、
E7（区分大小写），以及 D4 里「上下键在条目间走」。前三条都有等价的自动化
断言（`--outline-panel-self-check` 第 4 条、`--search-panel-self-check` 第 6
条、`ffi_search_matches_carry_utf16_and_block_bounds`）；E7 是已登记的欠账；
最后一条是 `NSTableView` 自己的行为。
