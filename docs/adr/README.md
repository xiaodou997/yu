## 何时写 ADR

只在决策满足下列任一条件时写：

- 改变了 [`invariants.md`](../specs/invariants.md) 中的某条不变量；
- 确定了一个跨 crate 的接口契约；
- 在两个都可行的方案中做了取舍，且理由不能从代码本身读出。

**不要**为「实现了某功能」写 ADR。v1 的教训是 ADR 数量增长快于能力增长，
最终 183 篇中多数在描述实现细节而非决策，反而增加了理解成本。

## 格式

```markdown
# NNNN. 标题

- 状态：提议 / 接受 / 取代（被 NNNN 取代）
- 日期：YYYY-MM-DD
- 相关不变量：A1, D4, ...

## 背景
## 决策
## 后果
### 正面
### 负面
### 引入的新问题与对策
```
