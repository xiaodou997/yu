## 场景与身份边界

默认同时保留 **4 个工作文档和 1 个纯文本哨兵窗口**。工作文档允许 2–12 个，压力时长允许 30–86400 秒。时长是完整轮次开始条件：已经开始的一轮会跑完，初始化、两段空闲、关闭、重开和像素检查另计，结果同时记录请求值与实际时长，不把上限写成精确运行时长保证。

每轮依次操作所有工作文档：有效公式与 Mermaid、无效 Mermaid、撤销与重做、纯文本。每个工作文档有独立窗口、文件与历史，使用现有 `native-event-driver.swift` 的外部事件接口，不直接调用编辑器内部命令。检查完整 AX 源码、纯文本资源回收及 BOM/CRLF 保存字节。工作文档增加后仍要求原应用 PID 唯一；helper 上界按工作文档数检查，不把单文档的“最多一个 helper”错误套到整个多文档进程。

压力后先在**所有文档与原历史都保留**的情况下观察空闲，再逐文档实际撤销／重做验证历史。随后正常保存和关闭工作文档，哨兵窗口保持原 PID，再观察关闭后的空闲。两段空闲都至少 70 秒，只有只读采样，不清历史、不刷新缓存。

接着在同一进程重新打开原文件，验证精确内容、资源重新出现、撤销到磁盘原文、保存和关闭。最后保存固定公式哨兵、完整退出、新 PID 冷重开、运行既有像素断言，再验证继续编辑、撤销、重做和保存。只有这些步骤全部完成且清理正常，`passed` 才表示**本次有限场景**成功；`group4_signoff` 始终为 `false`，`memory_verdict` 始终为 `not_determined`。

固定语料的每个文档／阶段有不同的 UTF-8 字节长度，正文包含中文、emoji 和 CRLF。原生日志目前没有稳定的文档 ID，因此长度只用于这个受控语料的计数关联，不能推广为用户文档身份：还必须核对 AX 窗口、完整源码和更新的 revision。所有权切换前增量消费并验证旧日志；新文档首帧要求空撤销／重做历史；同进程资源重开使用不同长度的标记；撤销后的帧要求新生命周期的历史计数。进程冷重开从新日志位置开始，不能复用旧 PID 的计数。

## 内存记录的解释

`events.jsonl` 逐条写入原生事件、文档开关、阶段与足迹，`result.json` 原子更新阶段摘要。应用日志增量读取，不在每次采样时重读全部日志；内存只保留一个有上限的未完成行、有限文档状态和阶段摘要。完整的坏 JSON、重复字段、非有限数、缺失或非法计数、观察到的日志截断／替换都会失败。所有权切换时未完成的日志行或超限积压也失败，不静默跳过证据。

应用和各 helper 的物理足迹分别记录。helper 在采样期间正常退出会标为 `exited_during_sample`，不会伪造成零内存。保留原生日志的撤销／重做条数、嵌入缓存、失败条目、GPU 纹理与逻辑 RGBA 字节、回收次数。每个文档的计数快照带实际观测时间；空闲采样不会制造新帧，沿用的快照明确标为 `last_settled_counters`，不能冒充同一时刻的全局资源普查。

重点比较 `churn_plain`、`retained_history_idle`、`closing_documents`、`closed_documents_idle`、`same_process_resource_reopen` 和新 PID 的 `cold_resource_reopen`。这些对照缩小下一次真机归因的范围，但**不能将物理足迹减去逻辑 GPU 字节后称为“历史占用”，也不能仅凭关闭窗口后下降就证明泄漏修复**。有限样本的端点、最小值和最大值不是长期稳定性阈值。需要进一步因果定位时，仍需与实际 Instruments／分配栈证据结合。

原生事件日志不为每次源码快照建立内存列表或独立文件，正常快照记录哈希；源码不匹配、原生驱动失败、像素失败保留具体文件与截图。结束记录构建清单、隔离后应用、helper、驱动、执行脚本、观测模块及既有像素模块身份。仅针对本轮隔离进程组进行有界失败清理，强制清理不能被计为成功。

## 本轮实际检查与真机入口

在当前 Linux 执行环境中实际运行：

```sh
python3 -m unittest discover -s tools -p 'test_group4_resource_soak.py' -v
```

**33 项工具测试通过。** 包括参数副作用、36 个语料长度槽、UTF-8 分段读取、坏／重复日志、读取与摘要空间边界、进程路径匹配、不同生命周期历史过滤，以及用假桌面运行真实编排后确认像素失败不能变为通过。这些不是 33 项产品实窗测试，也没有计入旧 Rust、Swift 或原生验收数量。

在测试 Mac 上先从当前 `main` 构建 Release 并核对 `.build/build-manifest.json`，然后从仓库根目录运行。需要 Python Pillow，以及现有原生驱动所需的辅助功能、事件发送和屏幕录制权限；桌面必须解锁。先用新的输出目录检查短场景链路：

```sh
python3 platform/macos/yu-shell-macos/run-resource-soak.py \
  --documents 2 --seconds 30 --idle-seconds 70 \
  artifacts/group4-resource-soak/short-light
```

短场景完成不替代长时压力。后续分别使用独立目录执行浅／深色：

```sh
python3 platform/macos/yu-shell-macos/run-resource-soak.py \
  --documents 4 --seconds 1800 --idle-seconds 70 \
  artifacts/group4-resource-soak/long-light

python3 platform/macos/yu-shell-macos/run-resource-soak.py \
  --documents 4 --seconds 1800 --idle-seconds 70 --dark \
  artifacts/group4-resource-soak/long-dark
```

这些命令是待执行入口，**本轮没有上述运行结果**。已有输出目录拒绝覆盖。若公式仍空白，保留失败结果和截图，不降低阈值、不删除像素检查，不把前面已完成的阶段升级为全场景通过。
