## 行为约定

连续选区的两个端点可能在不同层级。显式缩进／退一级时，先找到它们可安全共享的最近 `ul/ol`，再以其直接子条目为单位操作；从第一个到最后一个的完整条目及其子树一并处理。选中文字仍以原始端点映射，不扩大可见选区来冒充操作完成。

示例：父项正文至其子项的连续选区，以整个父项为单位；父项内的子项至同层后一个兄弟条目，以父项及该兄弟为单位。仅选某子列表中的条目，则仍只处理这些子条目，不额外提升它们的父项。

多个选区同时涉及父项和子项时，已选父项拥有该子树，子项不再移动第二次；即使父项选区位于子列表之后的尾段，结果也不能取决于选区处理顺序。同一层相邻或重叠的结构计划可合并；没有选中的间隔条目不能因粗暴合并范围而被额外退一级。

成功修改作为一个完整的列表编辑事务。所有选区的端点、方向、affinity 与主选区身份均需正确映射。顶层条目退出列表后，使用段落／容器保留其内容与必要属性；后续有序列表的编号按现有规则续接。中文、emoji、重复文字、注释、引号及不受影响的源码按共享语料逐字节核对，不能用文字搜索替代源码位置映射。

这一批扩大显式列表缩进／退一级到原生有限 HTML 独立列表及原生 HTML 表格单元格。**不宣称独立 HTML 的 Enter、Backspace、所有 HTML 布局或所有跨容器操作一并新增完成。** 既有表格列表 Enter、Backspace 和多光标行为仍需回归。

## 拒绝边界

一个连续选区跨两个单元格、跨 `details/summary` 等不透明容器、端点落在隐藏标签内部，或组合计划无法同时保持全部选区时，整个操作无修改；菜单可禁用，实际命令不得回退到只修改其中可处理的成员。

特别检查：一个非法 HTML 选区与另一个普通 Markdown 主选区同时存在时，不能因主选区是 Markdown 而执行半个操作。源码模式不应暗中启用 HTML 结构编辑。父项是列表首项且不能缩进时，同时选中的子项不能被单独缩进作为“替代成功”。独立的普通文本光标和已有首项无操作行为仍尽量按既有契约保留。

无法安全合并的复杂交叠保持拒绝，而非声称所有跨层级组合都已支持；不能因为拒绝安全而把尚未支持的功能勾选完成。

## 实窗执行方法

最低实窗组合：浅／深色 × LF 无 BOM／CRLF 有 BOM；通用语料同时测独立 HTML 与原生 HTML 单元格。已有 Rust 矩阵覆盖另外两种存储格式，实窗未执行的变体不要标成通过。

每个场景用全新输入副本：打开后核对 `expected-0.md`，末尾插入 ` HISTORY-A`，显式导航断开分组，再插入 ` HISTORY-B`，撤销 B。此时处于 `expected-a.md`，有 A 的撤销和 B 的重做。不要用等待时间猜测分组；建立失败就保留现场并重新准备。

采用产品实际 Command-] 缩进、Command-[ 退一级，以及现有菜单入口；不要假设 Tab 总是列表缩进，表格中 Tab 可能是单元格导航。

连续选区必须真实鼠标拖选或 Shift+键盘建立，正反方向都需检查。多光标用真实 Option 点击；先选父项再点子项，以及先选子项再点父项尾段都要覆盖。真实多光标与 `.case` 精确非空多选区是不同子项：后者可用既有原生命令／FFI 构造作契约补验，记录全部端点及主选区，但不可冒充真实拖选。

每次成功必须精确匹配该变体的 `expected-list-a.md`，只允许明确的源码结构变化；一次撤销回到 `expected-a.md` 并恢复原选区，重做恢复编辑后。成功编辑可以清除旧 B 的重做分支，这是正常行为。

每次拒绝连续三次实际发出命令，源码保持 `expected-a.md`，可观察选区保持不变。随后未做任何成功编辑时执行：重做 → 撤销 → 撤销 → 重做 → 重做，源码依次为 F2 → F1 → F0 → F1 → F2。只看到菜单灰掉不足以证明底层强制调用的原子性；底层对应 Rust 用例也必须运行。

| G4-L02-01 | `parent-child.indent`，父正文至子正文正反向选区后缩进 | 整个父项与子树只移动一次，子树相对层级不变；未选兄弟不变。 |
| G4-L02-02 | `child-next.outdent`，子项至父项外兄弟的选区退一级 | 按共同列表的完整条目处理，后续列表保留编号，端点仍在原中文字／emoji 边界。 |
| G4-L02-03 | `root-cross.outdent`，跨层级选区退出顶层列表 | p/div 结构符合预期，无嵌套列表塞入 p，两个端点分别正确映射。 |
| G4-L02-04 | `multi-parent.indent`，父／子／普通段落多光标缩进 | 父项拥有子树一次，普通段落光标只随前方字节变化映射；主光标不丢。另做 `.case` 非空多选区契约检查。 |
| G4-L02-05 | `multi-parent.outdent`，父与子多选区退一级 | 只退出父项一层，不将子项再单独退出；id、后续有序编号与历史保持。 |
| G4-L02-06 | `late-ancestor.outdent`，先选两个子项，再选父项尾段 | 操作仍由父项整体拥有，不取决于原选区顺序；重复文字上的光标不能互换。 |
| G4-L02-07 | `repeated-root.outdent`，多个根条目、多个重复文字端点 | 按 `.case` 做精确多选区契约检查；真实多光标补测选择相同受影响根条目。分别报告两种输入路径，不能合并证据。 |
| G4-L02-08 | `div-cross.outdent`，穿过透明 div 的父／子选区 | div 成对，原 id 仅一次，重开容器不复制 id；编号与父尾段保持。 |
| G4-L02-09 | `cross-cells.reject-outdent` | 连续跨单元格选区被整组拒绝，可处理的另一个选区也不改动。 |
| G4-L02-10 | `cross-disclosure.reject-outdent` | 不越过折叠语义边界提升共同祖先；另一个可处理选区不被单独修改。 |
| G4-L02-11 | `raw-endpoint.reject-indent` | 隐藏标签内端点只做 Rust／原生接口契约测试，不把它列作真实鼠标场景；整组保持不变。 |
| G4-L02-12 | `first-ancestor.reject-indent` | 首父项不能缩进时，已选子项不能自行缩进；拒绝后历史分支有效。 |
| G4-L02-13 | `mixed-markdown.reject-outdent`，非法 HTML 范围加 Markdown 主选区 | 不能落入主选区 Markdown 退一级，所有成员源码／历史保持。 |
| G4-L02-14 | 成功／拒绝各选代表完成保存、完整退出重开及中文组字 | 保存逐字节一致；整个进程退出再开，列表／编号／属性稳定；中文提交可撤销，取消不改源码。 |

多光标实窗的具体端点可能不同于语料的非空范围；必须记录实际选区前后并独立验证，不拿 `.case` 中另一组选区的位置冒充实测。无法观察的字段标为未观测；精确 affinity 等由 Rust／原生接口契约检查提供证据。
