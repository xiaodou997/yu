## 2026-09-19 第一轮：图片导入基础

新增 `NativeImageResources`：检查本地图片元数据及可解码缩略图；限定 128MiB、2 亿像素；复制原始字节到文档相对 `assets/`，独占创建唯一文件名，不覆盖原图片。路径配置拒绝空目录、绝对路径与 `..`，失败不发布源码引用。资源在撤销后保留，避免删除其他文档仍可能引用的文件。

Rust `local_image_markdown` 负责转义替代文字和 URI 路径；资源加载按 UTF-8 百分号编码解码一次。新增 revision-bound `yu_storage_session_insert_local_image`，按粘贴事务插入，一次撤销还原未修改的 CRLF 源文。

Mac 已接入“插入图片…”菜单、文件拖放和 PNG/TIFF 剪贴板入口。未命名文档先请求保存；取消时不复制资源。Swift 仅处理文件和原生事件，不解析 Markdown。

新资源层自检验证原始字节、重复导入不覆盖、中文目录、无效图片和越界目录无副作用；Rust 验证特殊字符序列能形成真正的 image widget、一次撤销/重做、FFI 无效参数/过期版本不修改源码。FFI 调整后执行 Swift package clean，并成功构建 arm64 release，应用哈希 `f92b9ecb45709899d1eb728173cfa525e3863ed3b6d23953bb4d1a4280b0d21d`。

本轮新增原生入口尚未通过真实窗口操作验收。仍需完成图片引用策略、另存为重定位、属性/尺寸编辑、失败重试与组合场景；3B–3D 尚待推进。当前默认复制策略不是最终完整设置能力。

## 第二轮：图片另存为与设置基础（进行中）

- 图片引用目录直接从共享语法树读取，引用式图片与引用/列表内图片都解析为源码区间；代码中的图片示例不当作资源。目录读取不填充正文布局缓存。

- 当前仍拒绝需要写入目标文档目录之外的相对图片路径，以及当前引用但已缺失的资源；此时不发布新文档。更友好的缺失资源保存/诊断、路径重定位策略仍需完善，不能据此宣称 3A 已全部完成。

## 第三轮：图片属性事务与接口（尚未接通原生面板）
