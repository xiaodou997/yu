## 3. 实际发现的 helper 漏报

生产代码把 `current_exe()` 的父目录拼接 `../Helpers/yu-document-renderer` 交给进程创建。系统实际命令显示为 `Contents/MacOS/../Helpers/yu-document-renderer`；旧 `process_rows` 仅匹配 `Contents/Helpers/yu-document-renderer` 的字符串前缀。

`process-identity-observation.json` 保存了同次进程列表：应用2097、4个真实 helper（2179、2229、2289、2339），旧解析器却返回 `helpers=[]`。第五轮四文档压力的365个内存采样也全为空 helper 列表。因此第五轮三套多文档入口关于 helper 数量、物理足迹、空闲退出及无残留的断言需要复验；这不抹掉对应源码、历史、窗口像素或应用物理足迹证据，也不自动否定使用不同进程观察器的冷重开／主题专项。

本轮原入口结束后，还使用新的内核探针独立核对其两个确切二进制路径，未发现残留。这个终点观察不能补造过程中漏掉的 helper 内存样本。

## 4. 观测链路修复

新增 `tools/process-inventory.c`，通过 libproc 的可执行文件路径和 BSD 进程身份匹配两个确切隔离二进制，不再使用命令行、argv0、basename 或任意字符串包含关系。目录中的空格、中文、换行、软链接和 `..` 不影响真实可执行文件身份。只查询当前用户，输出匹配进程的 PID、父PID、进程组和出生时间，不输出其他应用的命令行或路径。

同用户的部分系统管理进程不允许读取路径；探针单独报告这类无关不可读项数量。隔离组内进程不可读会失败，而不是伪造成 helper 为0；完整性受限的枚举和坏 JSON 同样拒绝。结果描述的是本轮隔离进程，不声称普查全系统。

多文档入口改为使用该探针，确认所有匹配进程仍在本轮创建的进程组内。有效资源帧及冷重开必须有一次实际非空 helper 观察，防止“永远返回空列表”的观察器继续通过。helper 物理足迹前后复核出生身份，正常退出或 PID 被替换时记录缺测状态，既不采纳别的进程内存，也不填成0；同一存活 helper 采样失败则仍失败。源码、撤销历史、缓存容量和原像素门禁均不变。
