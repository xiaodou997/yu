# fuzz 语料

## 这是什么

每个 `.md` 文件是 `tools/fuzz.sh` 找到过的一个失败输入，最小化之后入库。
`differential.rs` 每次运行都会把它们全部再跑一遍。

分工是清楚的：**fuzz 负责发现，corpus 负责不再复发。** 随机 fuzz 不能进
`tools/verify.sh`——那是一条以退出码为准的确定性门禁，塞进随机性就等于让
它偶尔说谎。所以随机的那半留在 `tools/fuzz.sh` 与它自己的 CI job 里，
而它的每一个产出都要变成这里的一个文件，从此由确定性的那半永久看守。

## 命名

| 前缀 | 含义 |
| --- | --- |
| `structural-` | 只验结构性质（C1/C2/C3/C5、不 panic）。输入可能落在不变量第 F 节的已登记偏差上，因此不与 comrak 比 HTML |
| 其他 | 同时要与 comrak 的 HTML 逐字节一致 |

文件名剩下的部分要能说清它抓的是什么，不要用编号或哈希——半年后没人查得到
`case-7f3a.md` 是干什么的。

## 加一个样本

1. `tools/fuzz.sh` 失败时会打印种子与输入，并把输入写进本目录；
2. 手工最小化到还能复现为止；
3. 按上表改名；
4. 跑 `cargo test -p yu-syntax --test differential` 确认它确实变红；
5. 修好之后再跑一次确认变绿，然后连同修复一起提交。

第 4 步不能跳过。一个不会失败的样本比没有样本更糟——它让人以为这一类问题
已经被看住了。
